# Certificate Rotation

## Overview

NKE tenant clusters use a self-signed certificate authority generated by kubeadm when the cluster is created. The NKE Controller keeps the certificates issued under that CA current without rebuilding the cluster:

- **Control-plane certificates** (kube-apiserver, kube-controller-manager, kube-scheduler, etcd, and the embedded `admin.conf` client certificate) are checked on a schedule and renewed before they expire.
- **Kubelet serving certificates** are requested by each node's kubelet and approved by the NKE Controller.
- **The cluster CA itself is not rotated.** It is valid for ten years from cluster creation.

> **Important:** Renewal restarts the control-plane components on one node at a time. On a cluster with a single control-plane node, the Kubernetes API is briefly unavailable during renewal. Run at least three control-plane nodes if uninterrupted API access matters to you.

## Control-Plane Certificate Renewal

Every certificate kubeadm issues to a control-plane component is valid for one year. The NKE Controller runs a renewal check for each tenant cluster on a fixed interval and renews any certificate whose remaining lifetime is inside a threshold.

| Setting | Default | Meaning |
|---|---|---|
| Check interval | 12 hours | How often each cluster is evaluated |
| Renewal threshold | 30 days | Certificates with less remaining lifetime than this are renewed |

Both are site-wide settings on the NKE Controller deployment; they cannot be set per cluster. Renewal is enabled by default.

### What happens during renewal

When a check finds a certificate inside the threshold, the NKE Controller starts a renewal workflow that visits the cluster's control-plane nodes **one at a time**. On each node it:

1. Confirms the control-plane containers are running.
2. Runs `kubeadm certs check-expiration`. If no certificate on this node is inside the threshold, it stops here with no changes.
3. Runs `kubeadm certs renew all`, which reissues every kubeadm-managed leaf certificate under the existing CA. Each renewed certificate is valid for another year.
4. Restarts kube-apiserver, kube-controller-manager, kube-scheduler, and etcd on that node by removing and restoring their static pod manifests.
5. Waits for all four components to return to Running before the workflow moves to the next node.

A node that fails any step is retried up to three times. If it still fails, the workflow stops without touching the remaining nodes. Nodes that were already renewed keep their new certificates.

Renewal does not restart tenant workloads or worker nodes.

### Renewal and downloaded kubeconfigs

Renewal updates the `admin.conf` stored on the control-plane nodes and in the management cluster. It does **not** update copies an operator has already downloaded with `nkectl get kubeconfig`. A downloaded kubeconfig stops working when its embedded certificate expires; retrieve a fresh copy before then. See [Tenant Kubernetes API Access](kubernetes-api-access.md).

## Kubelet Serving Certificates

Each node's kubelet is configured for server TLS bootstrap. It requests its serving certificate from the cluster as a CertificateSigningRequest and renews it the same way before expiry. The NKE Controller approves a request only when the identity in the request matches the node record NKE holds for that node: the requesting user, groups, key usages, common name, DNS names, and IP addresses must all agree. Requests that do not match are left pending.

No operator action is needed. A node whose kubelet certificate cannot be renewed stops reporting Ready.

## What Is Not Rotated Automatically

| Credential | NKE behavior |
|---|---|
| Kubernetes cluster CA and front-proxy CA | Not rotated. Valid for ten years from cluster creation. |
| Site controller (management cluster) certificates | No automated renewal. A documented manual, node-by-node procedure is planned. |

Operator-supplied CAs, automatic CA rotation, and certificate revocation are not yet supported.

## Verifying Certificate State

To inspect certificate expiry on a control-plane node:

```bash
sudo kubeadm certs check-expiration
```

To see the result of the most recent renewal run for a cluster, open the `RenewK8sCerts` workflow for that cluster in the Temporal UI. Each node's output and exit status are recorded in the workflow result.
